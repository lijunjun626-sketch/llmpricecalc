02 / FORMULA

Seconds, then tasks, then the published rate.

Rounding that a provider states per request is applied to each task. It is not applied once to the monthly sum.

seconds = hours × 3600, or minutes × 60
billed_seconds = seconds, or the next whole second when the provider says so
billed_seconds = billed_seconds × channels, only when that provider bills every channel
monthly_usd = billed_seconds × task_count × published_usd_per_second

A published hourly rate is divided by 3,600, and a published per-minute rate by 60, so the unit stays the official one. Amounts under $0.01 keep extra decimal places. $0.00 means the entered usage is zero, not that the API is free.

Modes are not substitutes.

Live, streaming, dynamic batch, and file transcription differ in latency and features. A lower number in this table is only a lower duration charge for that row. It is not a verdict that one API replaces another.

Those session rates are not multiplied by the audio length entered above. Text-to-speech, voice agents, and voice cloning are out of scope. Growth plans, committed-use discounts, and startup programs are not assumed.

05 / FAQ

Speech-to-text pricing answers

How is the monthly figure produced?

Each task is converted to seconds. If the provider says each request rounds up to one second, that happens per task. If the provider bills every channel, the channel count is applied per task. The task count is a whole number and is applied after that. The result uses the published USD duration rate.

Why can two rows with the same audio show different orders of cost?

They can be file versus live, standard versus dynamic batch, or different models. Features and latency are not equal, so the rows are not a single ranking.

Does $0.00 mean the provider is free?

No. $0.00 means the duration or the task count you entered is zero. Credits and the AWS introductory allowance are listed and left unused by this estimate. Amounts below one cent stay visible, such as $0.0045.
